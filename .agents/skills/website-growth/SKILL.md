# 网站推广增长

面向本仓库维护的网站 `https://strongduanmu.com/`。先找到限制增长的实际问题，再提出或执行可以验证的改动。不要把增加广告数量当成默认方案。

## Chrome 操作与隐私

- 按用户要求，通过 computer use 操作现有 Chrome 访问后台，复用正常登录态。不要从浏览器配置文件、Cookie 数据库、钥匙串或网络接口提取登录凭证。
- 优先使用后台标签页；需要前台操作时遵循当前用户偏好。如果用户明确禁止切换前台，后台连接失败不能自行改用前台。用现有工具文档中支持的接口操作，不通过 AppleScript、外部 CDP 或自建浏览器自动化绕过。
- 页面、弹窗和标签页切换后重新读取状态再操作；遇到用户切换页面时先确认域名，防止对其他工作标签页执行动作。后台连接超时不等于网站故障。
- **不得记录密码、Token、Cookie、验证码、会话标识、API 密钥、百度推送密钥或带鉴权参数的链接。** 不把原始页面树、完整后台导出、未脱敏截图和账号财务明细写入版本库。发布商 ID 是前端公开标识，不是登录凭证。
- Skill 保存入口、指标定义、检查方法和可复查的非敏感发现。需要保留原始报告时放在仓库外的本地缓存中，先筛掉身份与凭证信息；对外发布另行确认授权范围。
- 遇到验证码、权限或条款页面，明确说明阻碍，不把它记成“无数据”或“网站正常”。不代替用户接受新条款。

## 每次巡检

1. 读 `git status`，保留已有修改。确认站点属性是 `strongduanmu.com`，并区分域名属性、HTTPS URL 属性和账号总计。
2. 先看政策、手动措施、安全、抓取和索引异常，再看搜索机会与广告表现。只读巡检不隐含修改后台配置或发布广告实验。用户已要求对本站尚未收录的正式文章主动提交，可按下面的提交流程处理。
3. 默认比较最近完整 28 天与前一个 28 天；需要看趋势时补充 3 个月。后台默认周期不同就先记录原始周期，不把 90 天总计当月数据。注明观察日期、报告更新时间、统计起止日期、筛选条件和币种。
4. 抽查异常对应的真实 URL，再与本地源码、生成页面和线上状态交叉验证。区分尚未刷新报告、预期排除、已修复待抓取、仍可复现的问题。空图、不可见图表值和未加载状态记为“未取得”，不能补写成 0。
5. 给出少量高价值事项：证据、受影响页面、影响、建议、优先级、验收条件。修复后检查对应行为，再在同口径报告中观察后续变化。

## 未收录文章主动提交

用户已授权：巡检发现本站正式文章尚未收录时，可以通过 Chrome 搜索后台主动提交，并记录结果。先读最近巡检记录中的平台状态与待提交清单，避免重复提交已接受或已收录的页面。这个授权不包含定时任务、付费服务、API 密钥配置或扩大服务权限。

1. 从搜索后台取得具体 URL 样本，核对报告更新时间。先过滤站点地图、订阅、搜索 JSON、广告片段、分类和标签页等非文章地址，不把“未收录 URL 数”当成“未收录文章数”。
2. 检查候选页实际返回 200、canonical 指向自身正式地址、允许抓取和收录，且已经发布、有实质正文。排除草稿、noindex、已删除或重定向地址、重复别名，以及仅预习提纲、TODO 或未完成的页面。
3. Google 先用 URL Inspection 核验最新状态，对确实未收录的重点页 Request indexing；大量内容优先使用当前站点地图，必要时重新提交更新后的地图。已收录页无需反复请求，同一 URL 在一次巡检中不重复提交。
4. Bing 使用当前后台提供的网址提交、URL Inspection 或地图入口；只有在 IndexNow 已配置且不需要新密钥或权限时才使用既有机制。百度使用普通收录的手动或地图提交入口；不复制、保存或提交后台显示的推送密钥。
5. 只按界面显示的配额操作。出现限额或频率限制就记录待办并停止当前平台的重复请求；遇到验证码需用户完成，不能代解。其他平台不受影响的检查可继续。
6. 记录平台、日期、规范 URL、提交前状态及最终回执，区分“请求已接受／已进入队列”“地图提交成功”和“已收录”。没有最终回执不能记为提交成功；保留去重记录供后续复查，不承诺排名或收录时间。

Google 官方说明：[请求重新抓取与提交限额](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl)。提交不改变正文、页面标题展示、广告文案或已确认的拦截弹框。

## 观测指标与判断

| 方向 | 指标 | 如何找机会 |
| --- | --- | --- |
| 搜索表现 | 点击、展示、CTR、平均排名；查询、页面、国家、设备 | 高展示低 CTR 的页面检查标题与摘要；已有排名的主题优先完善内容和内链。不同查询、国家和排名下的 CTR 不能直接比较 |
| 收录 | 已收录、未收录原因、抓取日期、声明与搜索引擎选择的 canonical | 优先检查有内容却未收录的核心文章；草稿、预期 noindex、正确重定向不需要全部“修成收录” |
| 抓取 | 5xx、404、DNS/超时、robots 状态、抓取请求与响应耗时 | 用 URL 样本确认服务问题、内链错误或历史残留；不要把故意删除的页面批量重定向到首页 |
| 站点地图 | 提交状态、最近读取、发现 URL 数、抓取错误 | 对照 sitemap 是否只包含正式、规范、可访问的页面；区分地图成功读取与页面已经收录 |
| 内容与外链 | 缺失/重复/过短的 title、description，内部链接，外链来源 | 后台告警是线索。先读正文和搜索意图，补充准确自然的说明，不堆关键词、凑字符数或购买垃圾外链 |
| 阅读体验 | 移动/桌面 LCP、INP、CLS，广告是否遮挡、跳动或影响操作 | 区分真实用户报告与单次实验室测试；检查广告预留空间、滚动、关闭操作及窄屏布局 |
| 广告收益 | 预计收入、页面浏览量、页面 RPM、展示次数、展示 RPM、Active View 可见率、覆盖率（有提供时） | 先按本站筛选，再按设备、地区与广告单元拆分。页面 RPM 和展示 RPM 分母不同，不能互换 |
| 广告健康 | 政策告警、投放受限、ads.txt 状态、脚本是否加载、filled/unfilled、拦截恢复表现（有报告时） | 没有填充不代表广告被拦截；未显示广告也不代表账号被封。先查直接证据 |

收入情景计算：`预计收入 = 页面浏览量 / 1000 × 页面 RPM`。写明假设；小样本收入波动大，不能把界面优化目标说成已经验证的增幅。搜索点击、站点 PV、AdSense 页面浏览量是不同口径，不直接相加。

## 广告检查的硬约束

- **绝不点击真实广告**，包括广告图片、文字、箭头、跳转按钮和广告内的控制图标。不鼓励读者点击广告支持本站，不制造点击或重复刷新来增加展示。
- 实际页面只进行必要次数的打开与刷新；视觉、关闭和响应式测试优先使用本地预览。不要访问广告落地页来判断投放是否正常，不进入或操作广告 iframe 内容。
- 用户明确授权后，才临时改变广告拦截器设置；记录原始的本站/本页开关，做拦截与放行对照，最后恢复原状态。不要禁用其他安全保护，也不要清空浏览器所有站点数据。
- 本站使用可关闭的中央提示，提供放行步骤、继续阅读和手动刷新，关闭后 7 天内不再提示。保持“您”的称呼、网站主题色和居中的关闭图标。不能要求用户必须放行才能阅读。
- Google 的“广告拦截收入挽回”可以作为后续选项，但当前自建弹框不等于已启用官方功能；避免两套提示同时弹出。相关规则或功能变更时核对 [官方说明](https://support.google.com/adsense/answer/11576085?hl=zh-Hans)。

## 执行与复盘

先处理会阻止访问/投放/核心内容收录的问题，再处理元信息、内链和阅读体验，最后做需要较长观察期的增长实验。中文文章改写遵循仓库的 `blog-writing` skill；不自动开启已暂缓的全站英文版项目。

用户已明确要求：除已经确认的广告拦截提示弹框外，优化不得新增或改写页面可见文字，包括标题、导航、图片说明、广告位标签与正文。SEO 标题、摘要仅写入 head 元信息，不覆盖正文使用的 title、description，不添加隐藏关键词或额外页面标题；广告位原文为“赞助商”。验收时对照修改前的页面和源码，检查首页、文档目录、专栏、关于、动态、便笺与文章，以及广告标签、图片说明和标题层级，确认没有新增或改写可见文字；已有广告拦截弹框按已确认版本保留。需要调整展示时先取得具体授权。

改代码时读取实际版本和实现，局部修改、运行对应检查并构建；仅在现有授权包含提交推送时提交部署。上线后区分代码发布、实际行为验证、搜索引擎报告刷新和收入实验结果，不把其中一个替代其他环节。没有用户要求，不创建定时任务或自动发布推广内容。

复盘输出包括：本次发现、已完成改动、验证结果、尚未验证事项、下一观察周期。建议 2–4 周后按同周期同筛选条件复查；是否能归因于某次改动，还需考虑流量、地区、设备和季节差异。
